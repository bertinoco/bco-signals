Section 02

How it’s set up

Setup · Structure

Four folders and a rulebook.

docs/data/jobs.jsonThe dataset. One structured entry per role.
jd-source/The posting text, word for word. One file each.
jd-insights/Stats, quotes, patterns, findings.
jd-scout/The weekly search for new postings.
CLAUDE.mdThe rulebook: criteria and audit steps.
+ Visual
This is the README’s structure section. The dataset also publishes as the site at signals.bertino.co. CLAUDE.md is the file both Claude and I work from.
Setup · Data schema

What one entry holds.

titleVerbatim, as the posting words it.
clustersResponsibility areas, from the posting’s stated text.
signalsSkills and observable patterns.
compRangeMin, max, currency, and what the range covers.
quoteOne verbatim line that anchors the assignments.
+ Visual
Example entry to show on screen if you want one: CoLab, Content Systems Architect. clusters: content-systems-design, ai-tooling, enablement. signals: ai-native-expectation, content-marketing-adjacent. Other fields: company, domain, location, remote, sourceUrl, dateAdded, note. Two optional fields, quoteTranslatedFrom and titleTranslatedFrom, exist for non-English postings and render as a visible caption so a translation is never mistaken for verbatim text.
Setup · The taxonomy

Assigned only when the posting says so.

8 · 16

clusters and signals. A responsibility the posting doesn’t state doesn’t get the tag, however likely it seems.

+ Visual
8 clusters (responsibility areas) and 16 signals (skills and patterns). A new key needs evidence across multiple postings; a single instance is noted but doesn’t get one. That rule is in CLAUDE.md, Step 4 of the audit.
Setup · The archive

Every posting is kept, word for word.

131

archived postings: 78 in the dataset, 53 excluded with the reason written down.

Why

Nothing is cleaned up, and page chrome stays in. The archive is what every audit and recount reads from, so it has to be unedited.

+ Visual
One markdown file per posting in jd-source/, front matter plus the raw text. An excluded file records why, so the same posting isn’t re-audited from scratch or quietly added later.
Setup · Automation, finding

A weekly search finds candidates. A person decides.

1 DiscoverSearches for company boards not yet on the list.
2 PollReads Greenhouse, Lever, and Ashby job feeds.
3 FilterDrops anything already archived or already seen.
4 TriageA page where each posting is Audit, Later, or Skip.
Every Sunday

An unattended Claude Code session runs it. It never audits, writes data, or commits.

+ Visual
JD Scout, in jd-scout/. A scheduled Routine starts a fresh session that follows ROUTINE.md. Matching is keyword-based (title terms, plus body phrases for noisier matches). Postings from boards that never reach LinkedIn are the point.
Setup · Automation, audit

One posting, one confirmation.

EligibilityRequired criteria, then a signal test.
AuditClusters and signals from the text alone.
ReportWhat was assigned and why. New keys flagged, not created.
ConfirmI approve, or the posting is archived as excluded.
WriteEntry, archive, and stats updated in one pass.
/add-jd

A slash command. Subagents do the reading, so the main conversation only carries the decisions that need me.

+ Visual
This is the audit process in CLAUDE.md, run through the /add-jd command. Depth is a judgment call per posting: shallow for a clean match to an existing pattern, deep for anything borderline or new.
Setup · The loops

Checks that close the loop.

test_scout.pyEvery entry must pass the scout’s filter. If one wouldn’t have been found, the keywords get widened.
refresh.pyRegenerates stats and quotes from the data. Never edited by hand.
check-jobs-json.pyRuns in CI: unknown keys, duplicate ids, drifting counts.
asset version checkFails if a changed script or stylesheet ships without a version bump.
+ Visual
The first one is the real feedback loop: what the dataset includes tunes what the scout looks for. The asset check exists because a missed cache bump shipped a stale site twice.

What it found

Finding

The work moved from producing content to producing systems.

72

of 78 postings (92%), as of Oct 2026. A direct cluster count.

Not by writing content yourself, but by building AI-powered systems.
CoLab, from the dataset

Finding

Content standards are being pulled into central functions.

19

of 78 postings (24%), as of Oct 2026, on a close read. The raw tag count is 22.

…serve as Netflix’s centralized authority for scaling language standards.
Netflix, from the posting
+ Visual
MY TAKE: content design is being reconstituted as infrastructure, a small central group owning primitives and product teams consuming them. Not the only model: Wealthsimple is hiring for “You’ll be embedded on product teams.” A fork, not a replacement. GDS and Vinted carry the tag but don’t hold on a close read. Finding

AI fluency is a baseline, not a differentiator.

52

of 78 postings (67%), as of Oct 2026, expect the candidate to already work with AI tools.

Claude Code, Gemini, or Figma AI
HelloFresh, naming the tools

Judgment and taste are what’s asked for once AI does the drafting.

Each pairs judgment or taste directly against AI-generated output. Not a soft-skill throwaway.

My take

What’s left for the human once fluency is assumed.

This is a sharper version of the AI-fluency finding. That one says AI use is the baseline. This one says the postings draw a line between what the tool produces and what a person is still accountable for deciding is good.

Caveat

Five domains with no repeated employer is real spread, though SaaS accounts for four of the eight. This counts postings that use certain words. It doesn’t measure how much judgment the work needs.

Finding, in full

Evaluation infrastructure is generative work, built as software.

6

postings across five domains: Media, Big Tech, SaaS, Agency, E-commerce.

Generative content work authors a generator’s constraints and the criteria for judging what it emits. An eval harness is that criteria, operationalized as software rather than a hand-run rubric.

+ Visual
What the data shows, part 1. Count verified against the source texts as of Oct 2026: Spotify, Anthropic, Soda, Glean, Etsy (“set the eval framework that determines if the output meets the quality bar”), and Huge (“Develop golden queries and responses to benchmark quality and ensure safe, consistent outputs”). findings.md still says four companies in three domains; the live signal and the source texts say six in five.
What the data shows

The work, in the postings’ words.

Build evaluation frameworks to measure and improve conversation quality, accuracy, task completion, and user impact.
Spotify
Serious prompt engineering: multi-step LLM pipelines with structured outputs and evals, not chatting with a model.
Soda
+ Visual
Anthropic, verbatim from the posting: “Write and revise the prompts behind Claude’s tools, features, and behaviors on a product surface” and “Build the graders that prove a prompt fix and rerun on the next model.”
What the data shows

And what excluded the near-misses.

Create evaluations and guardrails for AI-generated and AI-maintained documentation, investigate failures, and improve the context, tools, prompts, and systems that shape output quality.

Audit work

My take

Hiring filters built on writing craft will undercount this.

The most technical generative-side postings gate on engineering skill, not a writing portfolio, because validating language at scale is an engineering problem even when the thing validated is language.

Caveat

Expect this signal to stay thin for a while. It names a real pattern, not yet a common one.

Finding

Nobody agrees what this work is worth.

Stated ranges run from $62,120 to $710,000. 51 of 78 postings state one, as of Oct 2026.

My take

An order of magnitude between roles with adjacent titles is not a seniority gap. It’s an absence of consensus about what the discipline is.

+ Visual
Insurify ($65,000 USD) and Netflix ($710,000) were the original endpoints and both carried “Systems” in the title. Don’t put comp on a slide as a comparison across currencies.
Finding

Content roles are appearing outside design orgs.

57

of 78 postings state where the role sits, as of Oct 2026, and placements don’t cluster in design.

What this can’t tell you

Four limits, stated plainly.

Not a market sampleAdmitted only if they pass a signal test. It says nothing about the median job.
No pivotsRole change inside an existing team produces no posting.
Existence, not rateAn excluded record proves a pattern exists, not how often.
A blind sideThe generative side is harder to catch than the deterministic side.
